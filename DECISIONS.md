# DECISIONS

Every judgement call made during the build, with the reason. Newest at the bottom.

| # | Decision | Why |
|---|---|---|
| 1 | Vite + TypeScript multi-page site. Page content lives in TS; each HTML file is a thin shell written by `scripts/gen-pages.mjs`. | One template per page type keeps all 26 pages consistent. Shells are committed so `vite` works without the generator. |
| 2 | `base: './'` (relative URLs). | The site works on GitHub Pages under any sub-path, and from a local preview. |
| 3 | KaTeX and fonts bundled from npm, not a CDN. | Works offline and on GitHub Pages with no third-party requests. |
| 4 | Colab badges point to branch `main`. | `main` is the repo's default branch. Branch names with `/` are unreliable in Colab URLs. Until this work is merged into `main`, the badges will not resolve; START_HERE.md explains the workaround. The branch is set in one place (`site/src/lib/config.ts`, `scripts/nb.py`). |
| 5 | The repo is private. | Colab can open notebooks from private repos after you tick "Include private repos" in Colab's GitHub tab. GitHub Pages on a private repo needs a paid plan, so START_HERE.md also explains running the site locally. |
| 6 | PyTorch installed from PyPI (CUDA build, runs on CPU here). | `download.pytorch.org` is blocked by this build machine's network policy. |
| 7 | Project Gutenberg is unreachable from the build machine. Showpiece B and the language-model notebook fall back to Tiny Shakespeare (public domain, from Karpathy's char-rnn repo). The notebooks still try Gutenberg first when run in Colab. | Brief: "If the download fails, log it and use any public-domain text available." |
| 8 | Wording check scans the *rendered* page text (with every `<details>` opened and every prediction revealed) plus notebook markdown, comments and strings. | Page text is built by TS at runtime, so scanning source files would miss or mangle it. |
| 9 | "Personification" rule flags third-person *wants / thinks / knows / feels / likes to*, not "you want to". | The brief bans describing maths objects as having wishes. Addressing the student is fine. |
| 10 | Colour language: green = input/data (v), red = weights (w), yellow = result. Blue/purple/teal = the three big ideas. | Brief 2a asks for consistent colour coding across all lessons. |
| 11 | Showpiece network: conv 5×5×8 → pool → conv 3×3×16 → pool → dense 64 → dense 10 (52,266 weights), trained 15 epochs on MNIST with random rotate/zoom/slant/shift/thickness augmentation. 99.4% test accuracy. | Small enough for a 1.5 ms forward pass in plain TypeScript; augmentation makes mouse drawings read reliably (400/400 messy test variants). |
| 12 | Drawing → 28×28 conversion re-renders the strokes with a fixed stroke width, fits them in a 20×20 box, then centres by centre of mass (as MNIST was prepared). Written as pure maths, not canvas calls. | Big and small drawings give the same input. The same code runs in Node, so sample drawings are unit-tested. |
| 13 | Map default is t-SNE; PCA is a second tab. The live dot in t-SNE mode is placed among the 10 nearest training digits (in layer-3 space); in PCA mode it is an exact matrix multiply. | t-SNE separates the ten digits cleanly (the 10-second wow). PCA is the linear-algebra link and shows why a flat projection overlaps. |
| 14 | Map uses 10 colours plus a white digit label on every cluster and a hover tooltip. | Ten categories can't be told apart by colour alone (dataviz guidance), so colour is a second cue. |
| 15 | "Why this answer?" uses occlusion (erase a 3×3 square, re-run, measure the drop in the top digit's score) rather than gradients. | It is literal ("erase a piece and see what changes"), so it follows the brief's "literal first" rule. The student can check it by hand with the eraser. |
| 16 | The draw pad, inside view and map are dark "instrument" panels in both themes. | Glowing grids need a dark background. The rest of the page follows the light/dark theme. |
| 17 | Challenges only count the student's own strokes, not the opening animation or Show me playback. | Otherwise the opening 3 would complete challenges with nothing at stake (reviewer finding). |
| 18 | Map/panel headings are questions ("How sure is it?") with a small label above. | Brief 2a: headings are plain questions. Reviewer finding. |
| 19 | Phases overlapped where the files were independent (helpers built field interactives while I drafted notebooks; the DSA player started while notebooks ran). Each phase is still reviewed and finished in order. | Faster overnight progress without mixing up phase quality checks. |
| 20 | Field interactives were built by four parallel helper agents with exact specs, each writing only its own files, with unit tests proving every challenge is winnable and every number in the card text is true. Text changes they found necessary were applied centrally. | Consistency (one template, one toolkit) and checked facts. |
| 21 | Field 1 → no "builds on" arrow from Classic ML. Two starting points in the learning lane (How models learn, Classic ML) plus Planning and search. | The brief numbers How models learn as field 1 and the most foundational; an arrow 2 → 1 contradicted the numbering (reviewer finding). |
| 22 | Calculus is shown as "used through training (Field 1)" (faded tag, hollow dot) for fields 3, 4, 5 and 10, whose maths lists in the brief don't name it. | Keeps the brief's lists intact while not misleading the student into skipping calculus (reviewer finding). |
| 23 | Gradient-descent interactive hides the error valley by default ("Show the whole valley" reveals it). | With the valley visible the student could read the answer off the graph, so stepping felt pointless (reviewer finding). It also matches what the algorithm can know. |
| 24 | Language-model challenge changed to "find a real word the model finds surprising" (a word from the plays with a letter pair under 1%), using a 4,732-word list from the same text. | The first version ("type a word whose letters are all top-3 guesses") was a word game with no insight (reviewer finding). The new one shows where counting one letter back fails. |
| 25 | Recognition cues keep the brief's "When you see ___ in a problem, think ___" wording on lesson pages; overview pages (Path Map) drop "in a problem". | The fixed wording read badly on non-problem pages (reviewer finding). |
| 26 | Field card layout: picture, "What you see" and "The formula" on the left; prediction, challenge, "What it means" and "What it's called" on the right. Long formulas render as display maths. | Brief 2a: "Put each formula right next to the picture it describes"; avoids formulas breaking mid-expression and a long empty column. |
| 27 | Notebook markdown is normalised by `scripts/nb.py`: the site's KaTeX colour macros (`\cg{}` …) become `\color{green}{}` …, and in "What it's called" blocks only the label stays bold (terms are italic). | Colab and GitHub don't know the site's macros (they showed red errors; reviewer finding). One bold idea per block (brief 2a). |
| 28 | Solution cells are executed during the check run, then their outputs are cleared before saving (`run_notebook.py`). | The run proves every solution works; saved outputs would show answers on GitHub before the student tries (reviewer finding). |
| 29 | `scripts/refresh_markdown.py` regenerates a notebook after a text-only change and keeps its executed outputs; any code change forces a full re-run. | Lets wording fixes land without re-running 4-minute notebooks, while never mixing new code with old outputs. |
| 30 | Field 7's predator–prey world gives rabbits fewer young as the field fills up (a carrying capacity of 1,000). | Without it, the first boom ended in both species dying out, so the "cycles" text was false. With it, five clear cycles in 600 steps. |
| 31 | Field 9's ordering demo compares 200 random exam orders with hardest-first, at 5 and at 4 slots. | With one fixed order the heuristic looked worse (26 vs 23 tries), contradicting the text. The honest result: hardest-first avoids the rare very bad orders (345 tries). |
| 32 | DSA visualisers share one step player (`site/src/pages/dsa/player.ts`); nine were built by parallel helpers from one brief, with sorting as the reference. Each proves its challenge, Show me and page numbers in unit tests. | Same controls on every topic; every number on the page checked. |
| 33 | DSA practice notebooks use a `check(fn, cases)` helper that prints ✓/✗ and never raises. | The notebook runs top to bottom unattended before the student has solved anything; the student sees exactly which case fails. |
| 34 | Practice sites are linked by section name (CSES "Sorting and Searching", USACO Guide "Binary Search", LeetCode tags), never by copied problems. CSES is described as "several hundred" problems. | Brief: link, don't copy. The exact CSES count changed over time and couldn't be verified offline. |
| 35 | Spark Log covers the ten fields only, stores one JSON object under `afe-spark-log`, and a second click on a score clears it. If storage throws, the page says so and Export still works. | Brief section 7. A private window must not lose notes silently. |
| 36 | Showpiece B: 5 layers × 4 heads × 128 wide, context 128, output layer tied to the character embedding: 1,016,320 weights. Trained 6,000 steps on Tiny Shakespeare on the build machine's CPU. Weights ship as float16 (2.7 MB). The browser keeps a key/value cache; past 128 characters the window restarts on the last 64. | "Roughly 1 million parameters, trained on CPU" (brief). float16 halves the download with no visible change in output (unit test compares to PyTorch). |
| 37 | Showpiece B challenges are measured, not judged, and ask for a boundary: "repeat" = a piece of 12+ characters appearing 3 times in 300 written, at temperature 0.2 or higher; "ramble" = at least 40% of words never in the training text, at 1.6 or lower; "attention" = find a head giving over half its attention to one character. Each Write starts again from the prompt and is scored on its own. Show me uses a fixed seed that reaches the goal (unit-tested). | Win conditions must be checkable (brief 2b). Sampling the model 24–48 times per temperature: at 0.05 every run repeats, at 0.5 none; at 2 every run rambles, at 1.3 none. Asking for the boundary makes the student explore the slider instead of moving it to an end (reviewer finding). |
| 38 | DSA challenge feedback appears only after the student touches the visualiser or presses Show me; Show me scrolls the animation into view. | The automatic first run was answering the prediction above it and describing an empty picture (reviewer finding). |
| 39 | DSA 10's challenge asks for two same-length words that need fewer edits than the number of differing positions (e.g. stone/tones: 5 differ, 2 edits). | The first goal (distance 1, 5+ letters) could be won with a plural, without reading the table (reviewer finding). |
| 40 | On phones, wide DSA drawings keep at least 540px and scroll sideways inside their box, with a hint. | Scaled to 350px, their labels fell to 7–9px (reviewer finding); the page itself never scrolls sideways. |
